01
지식베이스 사용법

이 문서는 GitHub Pages로 배포되며, Claude와 함께 지속적으로 업데이트한다. 내용이 추가되거나 수정될 때마다 새 파일을 받아 GitHub에 덮어쓰기하면 URL은 유지된 채로 내용이 갱신된다.

GitHub 주소: https://fvrtdara.github.io/ai-video-kb/

문서 업데이트 방법
1
Claude에게 업데이트할 내용을 전달한다.
예: "프로덕션 Step 2 내용을 이걸로 바꿔줘" → Claude가 GitHub URL을 fetch하여 최신 파일을 읽고 해당 부분만 수정한 전체 파일을 제공한다.
2
새로 받은 index.html 파일을 다운로드한다.
3
GitHub 저장소 FVRTdara/ai-video-kb 접속 → Add file → Upload files → 파일 드래그 앤 드롭 → Commit changes
4
1~2분 후 URL에서 업데이트된 내용을 확인한다.
테스트 로그 추가 방법
1
Claude에게 새 테스트 로그 페이지 생성을 요청한다. 사용한 프롬프트, Google Drive 영상 파일 ID, 인사이트를 함께 전달한다.
2
받은 파일을 GitHub에서 파일명 tests/test_01.html 형태로 업로드한다. 폴더가 없으면 자동 생성된다.
3
사이드바 테스트 로그 목록 및 09챕터 목록에 링크 추가를 Claude에게 요청한다.
Google Drive 영상 임베드 방법
1
Google Drive 영상 파일 → 우클릭 → 공유 → 링크가 있는 모든 사용자로 설정
2
공유 링크에서 파일 ID 추출: https://drive.google.com/file/d/파일ID/view
3
테스트 로그 페이지 생성 요청 시 파일 ID를 Claude에게 전달하면 자동 임베드된다.
02
왜 이렇게 만드는가 — 기술적 근거와 전체 흐름

이 문서는 생성형 AI를 활용한 영상 제작의 전체 프로세스를 정리한 개인 참고 자료다. 프리프로덕션(흐름 탐색 및 컨펌)부터 프로덕션(본격 제작 및 편집 조합)까지의 단계별 판단 기준과 자주 하는 실수를 담고 있다.

Seedance 2.0 작동 원리
이 프로세스가 만들어진 배경
  • Seedance 2.0은 레퍼런스 이미지와 프롬프트를 앵커로 영상을 생성한다.
  • 모델의 재량을 존중할수록 예측 불가능하지만 창의적인 결과가 나온다.
  • 제어를 높일수록 의도한 연출을 구현할 수 있지만 탐색 범위가 좁아진다.
  • 이 프로세스는 두 가지 균형을 단계별로 조율하는 방식으로 설계되었다.
4레인 앵커 아키텍처

Seedance 2.0에서 퀄리티와 일관성을 동시에 확보하려면 각 인풋이 명확한 역할을 가져야 한다. 역할이 겹치면 모델이 혼동하여 결과물에 블리딩(bleeding)이 발생한다.

레인담당 인풋역할침범 시 증상
연출 앵커스케치 스토리보드 (@img5)구도·카메라·샷 흐름포토리얼 스토리보드 사용 시 화질 블리딩
스타일 앵커캐릭터·배경·프랍 시트 (@img1~4)캐릭터·환경·소품 일관성레퍼런스 과다 시 우선순위 혼동
퀄리티 앵커키컷 고퀄 프레임 (@img6)비주얼 퀄리티 기준선 — 인물+배경+조명+재질의 통합 기준포즈 강한 이미지 사용 시 T2V에서 동작 고정
텍스트프롬프트조명·재질·분위기·모션외모 재설명 시 토큰 낭비·충돌
퀄리티 앵커 선정 기준
  • 그 앵글로 나와도 괜찮은 컨펌된 구도일 것
  • 배경 분위기와 조명이 잘 드러나는 컷일 것
  • 캐릭터에 라이팅이 제대로 적용된 컷일 것
  • 캐릭터와 배경의 합성 퀄리티가 자연스러운 컷일 것
  • 포즈가 지나치게 강하면 T2V에서 포즈 고정 이슈 발생 — I2V START FRAME 전용으로 활용
전체 프로세스 한눈에 보기
Pre-Production · 1단계
빠른 탐색 및 가편집
대략적 앵커 + 프롬프트로 720p 영상 다수 생성 → 가편집 → 타이밍·동선·컷 순서 확정
Pre-Production · 2단계
컨펌
관계자에게 흐름·동선 컨펌. 퀄리티·빛·앵커 정확도는 무시. 흐름만 본다.
Production · 1단계
앵커 정교화 · 스토리보드
씬 상태 반영 앵커 고도화. 실사 스토리보드 → 키컷 → 퀄리티 앵커 → 스케치 변환.
Production · 2단계
영상 6종 생성 및 편집
스케치 5종 + 프롬프트만 1종. 샷 단위 베스트 선정 → 편집 조합.
Production · 3단계
핵심 컷 집중 생성
베스트 반복 생성. 핵심 컷은 START FRAME + 프롬프팅으로 I2V 단독 생성.
Production · 4단계
부분 수정
Video Extend / Video Edit으로 특정 구간만 보정. 전체 재생성은 최후 수단.
핵심 원칙
  • 프리프로덕션은 최대한 러프하게. 타이밍과 동선만 잠그고 나머지는 전부 열어둔다.
  • 프로덕션은 탐색(6종) → 수렴(베스트 선정) → 집중(핵심 컷 반복) 순서로 진행한다.
  • 각 인풋이 자기 레인만 달리게 할 것. 역할이 충돌하면 결과물에서 블리딩이 드러난다.
03
프리프로덕션 — 흐름 탐색과 컨펌

프리프로덕션의 목적은 단 하나다. 컷의 흐름·타이밍·동선을 확정하는 것. 퀄리티·빛·앵커 정확도는 이 단계에서 중요하지 않다. 러프할수록 좋다.

1
빠른 앵커 + 720p 영상 생성 → 가편집
대략적인 앵커와 텍스트 프롬프트로 720p 영상을 여러 개 생성한다. 엉망진창인 영상에서 가편집을 통해 타이밍, 동선, 컷 순서, 연출 방향에 대한 감을 잡는다. 빛이 안 맞거나 앵커가 부정확한 것은 그냥 넘어간다. 흐름만 본다.
확정할 것
  • 총 몇 컷인가
  • 각 컷의 초단위 타이밍
  • 컷의 순서와 흐름
  • 캐릭터의 공간 동선
  • 180도 룰 (카메라 방향)
대략 정해지는 것
  • 샷의 대략적인 앵글 방향성
  • (와이드/미디엄/클로즈업)
  • 슬로우모션 구간 위치
열어둘 것
  • 세부 카메라 레이아웃
  • 정확한 카메라 무브
  • 연출의 강도와 스타일
가편집이 너무 그럴듯하면 안 된다. 컨펌하는 사람들이 그걸 기준으로 고정해버리면 이후 스토리보드에서 나올 수 있는 좋은 연출의 가능성이 잠긴다.

04
프로덕션 — 본격 제작

프리프로덕션에서 확정된 타이밍·동선을 기반으로 본격 영상을 생성한다. 탐색 → 수렴 → 집중의 순서로 진행하며, 단계를 거칠수록 생성 범위를 좁혀간다.

1
앵커 정교화
컨펌된 공간의 라이팅, 인물의 상태(더스트, 찢어진 옷, 땀 등 씬에 맞는 디테일)를 반영하여 앵커를 고도화한다. 캐릭터·배경·프랍 레퍼런스 시트를 고퀄리티로 완성한다.
앵커 정교화 단계에서 씬의 물리적 상태를 반영할수록 최종 영상의 일관성이 높아진다. 깨끗한 앵커에서 먼지 묻은 영상을 만들면 캐릭터 드리프트가 생긴다.
2
스토리보드 제작 — 실사 생성 → 키컷 선정 → 퀄리티 앵커 확정 → 스케치 변환
같은 흐름이지만 연출 느낌만 다른 실사 스토리보드를 GPT Image 2.0으로 생성한다. 생성된 스토리보드에서 키컷을 선정하고, 3×3 그리드로 변형하여 퀄리티 앵커를 확정한다. 퀄리티 앵커를 컨펌 받아 분위기를 확정한 후, 스토리보드를 스케치 형식으로 변환한다.
스케치 스토리보드를 쓰는 이유: 포토리얼 스토리보드는 화질이 Seedance의 비주얼 DNA로 잠겨 영상 퀄리티를 끌어내린다. 스케치는 구도·흐름만 전달하고 퀄리티에는 영향을 주지 않는다. 퀄리티는 앵커와 텍스트 프롬프트가 담당한다.

핵심 원칙
프리프로덕션 전반
러프함이 자산이다. 가편집이 너무 완성도가 높으면 관계자들이 그것을 기준으로 고정해버린다. 그러면 프로덕션에서 나올 수 있는 예측 불가능한 좋은 연출의 가능성이 닫힌다.
타이밍 확정
가편집에서 각 샷의 초단위 타이밍을 기록하고, 프로덕션 프롬프트에 그대로 명시한다. 이것이 가편집과 실제 영상 사이의 타이밍 드리프트를 줄이는 가장 현실적인 방법이다.
동선과 180도 룰
공간 동선과 180도 룰은 스토리보드가 아무리 연출을 다르게 해도 지켜야 할 물리적 뼈대다. 이게 흔들리면 편집에서 컷을 조합할 때 공간이 뒤집히는 문제가 생긴다.
역할 분리 원칙
각 인풋이 자기 레인만 달리게 할 것. 레퍼런스와 텍스트 프롬프트가 충돌하면 영상에서 텍스처 번짐, 모션 점프, 색상 드리프트로 드러난다.
스케치 스토리보드
Seedance는 스토리보드를 프레임 바이 프레임으로 복사하지 않는다. 구도·무드·카메라 흐름을 해석하여 자체 퀄리티로 렌더링한다. 포토리얼 스토리보드의 화질 블리딩을 막으려면 스케치로 변환해야 한다.
모션을 기술하라
Seedance는 이미지를 보고 있다. 텍스트 프롬프트 토큰은 모션 지시에 써야 한다. 외모를 다시 설명하는 건 토큰 낭비이자 충돌 원인이다.
I2V vs T2V
캐릭터 얼굴이 크게 잡히거나 오래 머무는 핵심 컷은 I2V. 빠르게 지나가는 동적 컷이나 와이드 샷은 T2V로 충분하다. 모션 컨트롤은 텍스트 프롬프팅으로 해결이 안 될 때만 사용한다.
해상도 전략
테스트는 720p. 같은 크레딧으로 720p 3번 돌리는 게 1080p 1번보다 낫다. 최종 퀄리티 확정 후 1080p+ 사용.
